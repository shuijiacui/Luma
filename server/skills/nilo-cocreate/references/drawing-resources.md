# 可检索绘画知识库

当前第一版包含 **28 个主题知识条目、29 类 57 张简笔画参考、14 组原创笔画步骤**。覆盖人物、猫狗兔、鱼鸟蝶、乌龟蜗牛、植物、房屋城堡、车辆船飞机、天象、水果蛋糕和雨伞；火箭、幻想角色和未知图形也有指导，不强制匹配图库。

资料分为三层：原画中有什么结构、哪些部件/互动值得添加、部件如何用短路径画出来。每条同时记录不适用条件，避免只靠图片类别套模板。

## 文件与来源

- drawing-knowledge.json：Luma 原创知识条目、适用条件、错误示范和 14 组 exampleAddition 笔画步骤。其余条目可使用既有部件编译器或模型自定义路径。步骤只描述新添部分的局部坐标，必须重新定位到孩子画上。
- drawing-library.json：已人工筛选的 57 张公开简笔画，含来源、原始简化笔迹、标识、署名、许可与变换说明。
- drawing-library-selection.json：审核后选定的分类和记录 ID；未选候选不进入运行时。
- 数据源：[Google Quick, Draw! dataset](https://github.com/googlecreativelab/quickdraw-dataset)，署名 Google Quick, Draw! contributors；[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)，见[官方许可](https://github.com/googlecreativelab/quickdraw-dataset/blob/master/LICENSE)。这是众包涂鸦，不能称为儿童专属绘画数据。分发记录或拼图时保留署名、许可、原始来源与修改说明。
- 图库示例在运行时等比缩放、重新绘线、换色和拼版。原创知识条目/笔画步骤与第三方示例的来源分别标明；不自动把示例整幅贴到孩子画上。

## 实际请求流程

1. 儿童端点击 Nilo，发送 `useDrawingKnowledge=true, drawingProtocol=3, turnScope="scene"`。先观察整幅画，观察阶段不添加笔画。
2. 根据观察检索相关知识与参考；识别不确定时仍保留想象性创作空间，不把资料当成识图结论。
3. 规划读取当前原画、知识与完整画法索引，选择一个相关新事物、画法、颜色、位置和比例。可以是独立对象，也可以使用目录外的自定义路径。
4. 程序通过 recipeId 检索实际笔画，校验路径、大小和边界，优先选空白位置但允许叠线；不再进行第二轮语义复核。数据无法绘制时使用模型自己选出的相关备选方案，必要时进行一次格式纠正。
5. 前端先显示可拖动、等比缩放的投影，孩子确认后提交。没有叶子／云朵选择菜单，不以随机线条替代失败；网络故障如实提示，原画保留。

这是推理时的资料检索，不是训练，也不是图像向量搜索；素材规模不能换算成模型的识图或共创准确率。旧部件连接与严格复核仅保留给兼容协议，见 [Nilo API](../../../NILO_API.md)。

## 用量与数据

v3 通常为观察、规划两次模型调用，最多一次格式纠正，共用 14 秒服务端预算。画法目录展示全部 ID 和姿态名称；只有前 12 个相关物体展开关联和建议颜色，笔画坐标留在程序内，不发送整套图库。扩展至 270 种未增加调用轮次。

普通语音聊天不增加这一步。儿童画面、观察文字与对话只在请求内使用；日志仅记录检索条数等汇总信息。资源在进程内缓存：使用 npm start 时修改后需要重启后端，开发 watch 模式会自动重载。原有 Quick, Draw! 参考继续保留来源与许可。

## 收集、审核与扩展

在 server 目录运行 node scripts/build-drawing-library.mjs：按知识条目中的 categories 从官方公开存储每类最多读取 128KB，生成每类三张候选及六类一页的联系图，输出到忽略目录 .tmp/drawing-knowledge。只获取数据，不下载执行远程代码，不获取全量数据集。

人工查看联系图，剔除语义模糊或不适宜参考的内容，在 drawing-library-selection.json 中记录保留 ID；再运行 node scripts/build-drawing-library.mjs --build。当前已审核 87 张候选，选定 57 张；这是一轮有限筛选，不能据此声称数据集整体已审核。新增主题还应补上可添细节、连接/摆放条件、失败示例，并为原创路径运行校验测试。

之后用合成画作跑 node scripts/check-nilo-cocreate.mjs --case=cat --live --check-canvas --details；--without-knowledge 用于对照旧流程，--local 用于检查运行中的后端。测试输出在 frontend/.tmp/nilo-cocreate，包含选中的参考图与实际添画图，不读取真实儿童作品。canvasFits 仅代表几何可以落笔，必须另外人工评价相关性、重复、方位、大小和孩子是否还有继续画的空间。

## 完整事物画法（2026-09-21）

`shared/niloRecipes.mjs` 统一导出 **90 类、270 种** Luma 原创可执行线稿，每类 3 种画法。保留原有 18 类；新增 72 类：动物 18 类、植物天象 12 类、交通建筑 12 类、食物 12 类、物件玩具 12 类、幻想角色 6 类。分别在 `niloRecipesAnimals/Nature/Places/Food/Objects/Fantasy.mjs` 中维护。

变体改变姿态、轮廓、构成或细节，例如长颈恐龙／霸王龙／剑龙、全身／坐姿／头像、开花／盆栽、敞篷车／厢式车；不是换色或镜像副本。素材保留具名部件，支持整组移动、缩放、换色和换画法。中英文名称共用匹配规则，避免把“熊猫”选成“猫”、把“鲸鱼”选成“鱼”。不是下载训练权重；原有 57 张 Quick, Draw! 参考保持原署名。

规划先结合场景选择新事物与 recipeId，编译时检索目标物体的可执行笔迹、部件分组和最低显示尺寸。v3 校验坐标和命令预算，空白位置优先但允许叠线；图库外主题仍可用自定义路径。近期 recipeId 参与排序，不保证模型永不重复。

已离线渲染检查全部 270 种线稿，并通过路径、部件与几何校验；这是助理视觉检查与程序测试，不是儿童盲评。内部部件标注支持尾巴、翅膀、船帆等局部变换；已有自定义路径缺少部件标注时不会猜测并移动其笔迹。

素材附带建议配色；模型可根据画面另选颜色，建议色不是强制调色板。按物体合并候选目录，避免每个变体重复发送主题和配色，仍向模型提供全部 270 个 ID。
