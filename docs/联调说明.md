# 前端联调说明（给搭档）

> 后端判定服务已完成（server/，39 单测全绿）。本文档是 Luma 前端接入的最小说明，详细 schema 以 [API契约.md](API契约.md) 为准。

## 1. 启动后端

```bash
cd server
cp .env.example .env   # 填入真实 LLM_API_KEY
npm install
npm start              # http://localhost:3001
```

## 2. 前端连通（二选一）

Luma 的 `src/config/env.ts` 默认 `apiBaseUrl = '/api'`，当前 vite.config.ts **没有配 proxy**，二选一：

**方案 A（推荐，不改代码）**：`Luma/frontend/.env.local` 加一行：

```
VITE_API_BASE_URL=http://localhost:3001/api
```

后端已开宽松 CORS（Demo 无账号体系），跨域直连即可。

**方案 B**：vite.config.ts 加 proxy：

```ts
server: { port: 5173, proxy: { '/api': 'http://localhost:3001' } }
```

## 3. 页面 ↔ API 映射（对应交互流程.md）

| 页面 | 调用 | 说明 |
|------|------|------|
| P2 画板完成 → P3 AI 反馈 | `POST /api/analyze` | body: `{ imageBase64, priorFeatures: null }`；画布导出 PNG → base64（**去掉 `data:image/png;base64,` 前缀**） |
| P4/P5 补充绘画 | `POST /api/analyze` | `priorFeatures` 传上一轮返回的 `features`，server 自动合并（元素并集、涂改累加） |
| P6 结果页（家长视角） | `POST /api/report` | body: `{ features }`（用最后一轮 analyze 返回的 features） |

## 4. 展示注意

- **孩子视角全程不展示判定结果**（红线）：`/api/report` 只在家长结果页调用
- `emotion` 六种取值：`乐观平稳 / 未见明显风险信号 / 焦虑倾向 / 低落倾向 / 需要关注 / 信息不足`，前端按枚举做展示分支，不要自己做阈值判断
- `confidence` 直接展示数值（已含 0.85 天花板），不要四舍五入成 100%
- `feedbackText` / `followUp` / `parentAdvice` 都是后端模板文案，**前端不要改写**（防诱导措辞红线）
- `evidence[].entryId` 可在结果页展示为"判定依据"溯源标记

## 5. 健康检查

`GET /api/health` → `{ "ok": true }`，联调前先验证。
