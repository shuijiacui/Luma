# 引导体系与反馈边界

> 当前实现，2026-09-14。此文描述新手指引及产品话术约束，不把早期讨论中的心理机制猜测作为研究结论。

## 新手指引

家长端首次引导共四步：连接／切换孩子、近期创作概览、创作记录入口、周报与月报入口。未连接孩子时先打开家庭设置并定位真实邀请码，随后返回概览；真实家庭信息和创作记录加载完成后才启动。沟通助手、家庭设置分别在首次进入对应分区时介绍；设置里的「重新看新手引导」可以重看首次流程。

儿童首页首次引导包括摸摸 Nilo 的头、推门进入画布，亮起的区域可以直接操作。画布引导在欢迎界面关闭后开始，依次介绍快捷颜色、试画一笔、撤销、保存。完成一笔绘画后才自动前进，保存步骤只介绍操作，不替儿童保存。首页及画布的「怎么玩」按钮均可重看，每一步也可以选择下一步或以后再看。

家长采用奶油白和浅绿色浮动卡片，儿童采用带 Nilo 头像的较大字号气泡。高亮取当前可见元素并裁剪到滚动容器和可见视口；定位使用说明卡实际高度，自动选择相邻空间，兼顾设备安全区域与浏览器可见视口变化。短屏上的长说明可在卡片内滚动，不固定盖在底栏之上。

点击遮罩不结束指引。阅读步骤拦截背景操作，互动步骤仅开放目标区域；支持上一步、Escape 退出、Tab 焦点约束、退出后恢复焦点及减少动画设置。页面卸载会取消所属指引，避免将遮罩带入下一页。

### 配置与维护

- 步骤配置：`frontend/src/features/onboarding/steps/`。每步使用稳定 `id`、定位选择器、标题、说明；可配置 `prepare` 打开分区、`interaction` 指定真实点击或笔画完成、`focusArea` 限定大目标中的操作区域。
- 同一功能在电脑和手机上可以使用相同 `data-onboarding`；定位器遍历匹配项并过滤隐藏元素，不再只取第一个元素。页面重构时要同步检查目标，不能用大面积容器替代精确按钮。
- 目标准备失败或连续 3 秒不可用时跳过该步骤；若存在不可用步骤，本轮不会被记录为完整完成。异步准备、视口变化、滚动和目标尺寸变化都会触发重新测量。
- 记录键为 `luma_onboarding_v2:<角色>:<账号>:<流程>`。正式账号区分 `completed` 与 `skipped`，两者都不会在每次进入页面时打断用户；游客只保留本次浏览器会话记录。记录保存在本机浏览器，不跨设备同步；旧的角色级记录不再用于判断新版指引。
- 引导文案需同时维护 `shared/locales/en.json`，不要暗示沟通助手已经支持自由输入或将画面解释为孩子真实心理状态。
- 回归验证见 `frontend/tests/onboarding.test.tsx`，覆盖可见目标选择、视口避让、异步目标、互动、键盘、账号隔离和空家庭完整流程。布局数学与 DOM 测试不能代替真实设备视觉验收。

## 创作反馈与解释边界

儿童侧以描述画面和开放提问陪伴作画。`buildFeedback` 将可见元素、颜色及构图组织成模板，固定 followUp 为“想再画点什么吗？”。不调用文本模型生成儿童心理解读，也不对孩子展示家长报告。

每次识别当前完整快照，不计算“又增加了哪些元素”，也不使用历史并集评价新的画面。数字画板反馈与评分排除未测量的真实笔压和擦除次数证据。

儿童反馈不应暗示情绪答案、替孩子命名感受或把单幅画解释为现实状态。画面内容也可能被模型识别错，不能把模板输出称为不会失真的客观事实。

家长 parentAdvice 由基础模板与命中簇建议组成；另可通过受约束的文本模型生成 narrative、证据通俗化及联网建议。增强有输出校验和整体等待预算，失败保留基础结果。说明与文献背景不改变评分。

家长沟通助手把已有建议呈现为可展开的提示卡，不是自由输入的聊天机器人；长期记忆和多轮对话没有实现。UI 中的 AI 描述必须标明来源，不能标成孩子原话。

具体文案以 `server/src/services/report.js` 为准，接口以 [API 契约](API契约.md) 为准；产品输出语义见 [情绪输出标准](情绪判定标准.md)。
