# 先构思后检索：小规模对照

结论：已实现可切换的试验流程，但本轮没有证明整体效果更好，因此不替换默认流程。素材目录与构思可以分开；接下来更需要解决复杂物体的路径表达和布局，而不是单纯扩大素材数量。

## 两种流程

- 原流程 `catalogue`：观察画面，再在包含 270 个画法 ID 的提示中同时决定主意和画法。
- 试验 `idea-first`：第一轮看画面与孩子的话，输出主意、与画面的关系和必需细节；此时不提供画法或课程目录。之后本地按主意的中英文名称/关键词检索最多 6 个候选，将实际路径交给第二轮绘制。没有匹配时为空候选，仍允许自绘。

试验允许直接选匹配画法、参考少量路径后自绘、完全自绘。第一轮判定需要组合或特殊改造的主意不能直接退化成普通库内物体。最多一次绘图格式修复，只修复原主意；失败后返回不可用。名称和关系锁定不代表路径已经表达全部细节，也不能代替视觉验收。

通常仍为两次模型调用，最多三次，共用原有截止时间和取消信号。客户端仍收到 v3 完整绘图方案。`drawingMetrics` 增加 `creativeMode`、`candidateCount`、`route` 和 `referenceReported`；后者仅表示模型声称参考了某个候选，不能证明复用了哪些笔画。正常 trace 只记录候选数量，不记录新增主意文本。

## 本次实测

时间：2026-09-21。模型：项目已有 `deepseek-v4-flash-vision-exp`。使用已有的 6 张合成画，每种流程各跑一次；3 个开放创意请求、3 个明确组合请求。两种流程交替先后执行，每次总预算 14 秒，不挑最好结果，不删除失败项。模型未看到作者标注或评分标准。它们是复用的开发样例，不是未见测试集，也不代表真实用户使用率。

| 项目 | 原流程 | 先构思后检索 |
| --- | ---: | ---: |
| 成功生成可渲染方案 | 6/6 | 4/6 |
| 最终直接使用库内画法 | 4 | 0 |
| 最终自定义绘图 | 2 | 4 |

注意：两组提示词与输出预算不同，这是流程改动的一部分。token 数量下降不能直接解释为同等比例的费用下降，也不能抵消失败或质量问题。

检查真实成图后：

- 仙人掌：原流程画出飞碟；试验想画“戴草帽的沙漠小蜥蜴”，但第一份数据包含越界控制点，修复又产生只有移动、没有绘制的笔画，最终未出图。
- 小鱼：原流程画出旁边的潜水艇；试验画“戴礼帽的鱼”，却把新鱼叠在原鱼里面，位置和主意的表达不理想。
- 单眼三足角色：原流程画蝴蝶；试验想画带轮鞋的小怪物，先出现解析失败，修复数据又把独立笔画/椭圆混排，最终未出图。
- 飞茶杯：两组均有自绘结果；试验将杯子放在茶壶内部，杯把与翅膀的区分也不清楚。
- 太空兔子：原流程用了普通兔子画法，实际没有头盔；试验没有直接退化成普通兔子，但成图中的兔耳与头盔仍不清楚，颜色也过浅。不能凭方案名称判定成功。
- 会走路的花：两组均自绘；试验脚的结构更明显，但花瓣辨识度和与原有花朵的布局仍需改进。

因此，当前只能说试验更愿意提出组合创意，不能说它更会画。后续优先方向是：少量稳定基础形状加明确的部件组合、可靠的路径格式与尺寸布局，再用新的画作验证。素材库按实际缺口增长即可，无需以无限扩容或高自定义率为目标。

## 重现和切换

服务端设置 `NILO_CREATIVE_MODE=idea-first` 并重启可开启；不设置或设为 `catalogue` 保持原流程。只影响 v3 接力，不修改客户端协议，不把用户传入的 context 字段当作开关。本次没有修改实际 `.env`。

从 `server` 目录运行 `node scripts/check-nilo-idea-first.mjs` 仅生成离线待测材料，不发送模型请求；加 `--live` 才沿用项目配置运行 12 个模型回合。每次创建独立时间目录并持续保存失败和成功记录。只支持脚本内的合成画。
