# AI 解读与知识库

本文统一说明画作特征、知识检索、评分、报告输出与可选文献增强。用户操作见 [功能与使用流程](功能与使用流程.md)，接口见 [API 契约](API契约.md)，配置见 [部署](部署.md)。研究来源和结论边界见 [研究依据](研究依据.md)。

Luma 是创作陪伴与观察参考系统，没有经过临床有效性验证。给定同一组特征、知识库和配置时，评分可复现；这不意味着视觉模型识别正确、输出完全确定，或报告分值是心理健康概率。

## 两类 AI 工作与两条检索路径

| 工作 | 实现与作用 | 边界 |
| --- | --- | --- |
| Nilo 共创 | 视觉/文本模型根据画面与孩子的话规划相关提案，前端投影和检查，孩子明确确认才落笔 | 生成内容不是孩子独立表达；细节见 [Nilo API](../server/NILO_API.md) |
| 画作解读 | 视觉模型提取特征 → 结构化知识匹配 → 代码评分 → 基础报告及可选说明 | 模型不直接决定基础报告分值 |
| 结构化检索 | `knowledge/entries.jsonl` 与 `constraints.json`，标签匹配、年龄与冲突规则 | 基础报告不需要向量数据库 |
| 文献检索 | `docs/references/*.pdf` → Python / LlamaIndex → 本地 Chroma → 文本模型过滤 | 只补研究背景和局限，不改变评分或自动写回知识库 |

共创观察使用孩子与 Nilo 已确认的合成画面，成长解读使用分离出的孩子笔迹。共创报告仍标记创作选择可能受到合作过程影响，不能宣称完全独立绘画。旧 PNG 的作者来源未知时保留作品，但拒绝新的儿童特征分析。作者标签来自保存的操作文档，不是对上传内容的独立鉴证。

## 特征与质量门控

实现：[extractFeatures.js](../server/src/services/extractFeatures.js)。模型先给 `rawDescription`，再输出元素、主色和深色比例、构图、异常特征、涂改数，以及逐维 `confidence`。服务端执行类型、枚举、长度和数值范围验证。

逐维自报置信度低于 `0.5` 时，该维度清空或中性化，不参与匹配。这个自报值没有样本校准，**只用于门控，不乘入评分权重**。`rawDescription` 保存用于回看核对，不证明描述正确。每次处理完整快照，旧 `priorFeatures` 不做增量累加。

数字画板没有测量真实笔压或可用于这些规则的擦改历史；`source: "digital_canvas"` 排除依赖 `composition.pressure`、`erasureMarksMin` 的知识条目。操作文档中存在橡皮记录，也不等于已经接入心理解读证据。

儿童反馈由客观特征与模板生成，包含描述及开放提问，不展示家长分类。中英文反馈来自相同特征，不额外调用翻译模型。儿童身份不能读取正式家庭报告、趋势或周期摘要；AI 对画面的描述不能标作“孩子原话”。

## 知识层与调度

当前 `entries.jsonl` 共 31 条：L1 26 条、L2 3 条、L3 2 条。每条包含 `id`、`tier`、`featureMatch`、`emotionSignal`、`cluster`、`strength`、`reliability`、`source`、`note`。L4 位于 `constraints.json`，提供年龄、冲突与输出约束。层名是策展分类，不表示产品已经获得对应实证效度。

运行期实现：[retrieve.js](../server/src/services/retrieve.js)、[kbDispatcher.js](../server/src/services/kbDispatcher.js)。顺序如下：

1. 一条规则的全部 `featureMatch` 条件必须满足；未知字段不命中。元素与异常数组要求指定项全部包含，主色匹配至少包含候选之一，其他条件按阈值或枚举比较；旧笔压值 `weak` 兼容 `light`。
2. 数字画板排除笔压和擦改规则，记录丢弃原因。
3. 对 `ageMods.affectedEntries` 指定条目，将相关维度自报置信度乘年龄系数，再过 `0.5` 门控：当前 4–7 岁乘 `0.5`，8–12 岁乘 `0.8`。这是保留/丢弃，不是将权重减半。正式报告年龄按家长填写的生日与生成时日期计算；忽略客户端年龄，未填生日不推测。
4. L3 条目仅在同一情绪组已有 L1 命中时保留。
5. `CONFLICT-01` 两项同时命中时移除 weather 簇；`CONFLICT-02` 对擦改条目要求 line_quality/heavy_pressure 支撑；`CONFLICT-03` 的限制已在条目数据中，不在运行期再减权。
6. 按 `strength × reliability` 排序，输出命中、冲突和丢弃记录。

知识校验命令 `node knowledge/scripts/validate.mjs` 检查 ID、来源、匹配字段、权重、层级范围及强度上限。L1/L2/L3 的 strength 上限为 `0.6 / 0.2 / 0.2`；运行期调度器不是通用规则解释器，不会每次自动改写所有条目的强度。

## 评分公式与决策顺序

实现：[score.js](../server/src/services/score.js)。对同一情绪组计算：

```text
w_entry   = min(strength × reliability, 0.9)
w_cluster = max(同组同簇条目权重)
E         = 1 − ∏(1 − w_cluster)
S         = E × prior / (E × prior + fpr × (1 − prior))
展示值    = min(S, ceiling)
```

当一组全部证据来自 L2/L3 时，`E` 最大为 `0.6`。这是证据合成上限，**不是 S 上限**，不能据此推断“一律信息不足”。簇内 max 减少重复计数，但不证明不同簇统计独立。`crossClusterDiscount` 仍是预留参数，没有生效算法。

`strength`、`reliability`、`prior`、`fpr` 均为策展或配置参数；E 不是实测似然，S 不是校准后的贝叶斯后验。当前默认负向 prior `0.15`、积极 prior `0.60`、fpr `0.05`、主阈值 `0.7`、弱信号线 `0.4`、候选差距 `0.1`、方向冲突线 `0.5`、展示上限 `0.85`。排名使用未截断 S，展示才应用上限。

按以下顺序执行，不能简化为“低于 0.7 就信息不足”：

1. 所有特征维度均为空：`信息不足`，分值 0，`reason=extraction_failed`。
2. 原有匹配但引用 ID 全部无效：`信息不足 / invalid_evidence`。有效特征没有命中：`未见明显风险信号 / zero_hits`，空证据，分值使用积极 prior（默认 0.60），不是积极证据。
3. 任一负向组 S ≥ 0.4：积极组移出主候选。
4. 以下条件依优先级命中任一，输出 `需要关注`：负向组处于 `[0.4,0.7)`（4a）；两个负向组均 ≥ 0.7（4b）；第一候选 ≥ 0.7 且领先不足 0.1（4c）；有强负向组且积极组 ≥ 0.5（4d）；强负向组只由一个簇支持（4e）。
5. 否则，最高候选 ≥ 0.7、领先至少 0.1，且负向候选至少有两个簇，输出该倾向，`reason=main`。
6. 其余输出 `信息不足 / fallback`。最终条目证据或输出文案触及红线时降级为 `信息不足 / redline`；建议文案另有输出校验。

`assertConfig` 检查负向阈值在 E=1 时理论可达，即 `fpr ≤ prior × (1 − threshold) / (threshold × (1 − prior))`。它只验证数学配置，不验证漏报率、误报率或真实儿童表现。

## 六类输出的呈现约束

| 输出 | 工程含义 | 不应扩展为 |
| --- | --- | --- |
| 乐观平稳 | 积极组满足主分支条件 | 孩子整体健康或未来状态的保证 |
| 未见明显风险信号 | 有效特征在当前知识库中零命中 | 乐观平稳、积极证据或已排除实际问题 |
| 焦虑倾向 / 低落倾向 | 对应负向组满足主分支与至少两个簇要求 | 疾病诊断、个体医学概率 |
| 需要关注 | 弱信号、冲突、候选接近或单簇强信号 | 必然超过主阈值的结论 |
| 信息不足 | 特征不足、引用无效或兜底/输出校验失败 | 自动替换为积极或稳定 |

接口沿用 `confidence` 名称，界面应解释为“参考分值”。默认 0.85 只是配置上限，不是文献测得的准确率或效度天花板。视觉模型的逐维 confidence 与报告分值也不能混用。

趋势只汇总已有报告，`stable` 代表近期有效结果没有关注标签，不是现实心理状态保证；`watch` 与 `insufficient` 按历史接口规则计算。周报/月报不生成新情绪分类，不将作品数、天数或元素频率换算为想象力、表达意愿或情绪百分比。

## 报告增强与文献 RAG

实现：[routes/analyze.js](../server/src/routes/analyze.js)、[report.js](../server/src/services/report.js)。先产生基础报告，再按条件生成家长说明、证据白话说明、文献背景和联网建议。所有增强共享 `REPORT_BUDGET_MS`（默认 20 秒，最大 30 秒）；失败或超时保留基础结果。增强不能修改基础标签和分值，也不回写知识库。新增报告按 `locale` 生成语言，历史自由文本不因界面切换自动翻译。

Bocha 只使用亲子陪伴/沟通主题查询，不能把网页内容当作新增评分证据。文本模型输出经过字段、长度、引用来源或红线校验，这些检查不等于逐句事实验证。

文献索引使用 `chunk_size=300`、`chunk_overlap=60`（LlamaIndex tokenizer 计量，并非固定汉字数），保存来源文件名及 SHA-256。运行时检索 Top-5，过滤相似度低于 `0.40` 的片段，再经文本模型筛选。服务端验证引用文件属于检索候选，返回 `role: "reference_only"`。相似度只表示检索相关性，不是心理参考分值。引用与结论仍需人工核对。

基础评分无需 Python；文献检索需可用的 Python、依赖、PDF 索引及 `RAG_EMBED_*` 服务。Node 通过子进程调用检索脚本，未运行独立的常驻检索服务器。配置步骤见 [部署](部署.md) 与 [rag/README](../rag/README.md)。

家长“AI 沟通助手”当前展示已有报告建议和固定开放问题，没有独立自由聊天模型接口。不要把该名称与儿童 Nilo 对话接口混同。

## 配置的实际生效范围与审计

| 配置来源 | 当前读取内容 |
| --- | --- |
| `entries.jsonl` | 匹配条件、条目层级、簇、权重、策展文案 |
| `constraints.json` | 年龄调制、已实现的冲突登记、输出红线、知识版本组成 |
| `dispatch.config.json` | app 读取 L2 的 `groupEvidenceCap` 作为全 L2/L3 组的 E 上限 |
| `score.js` 默认值与服务端环境变量 | prior、fpr、主阈值、展示上限；变量见 [部署](部署.md) |

`dispatch.config.json` 的其他 policy、decision、indexes 等字段不是动态可执行规则。现有 `rulesVersion` 中的 v2.2/旧文档名称是历史标签，具体顺序以 `score.js` 为准。`constraints.json` 中 fpr、priors、validityCeiling 的解释性字段也不能替代 app 实际读取的默认值与环境变量；例如运行默认 fpr 为 0.05，不是该文件保留的 0.30 讨论值。论文数字与注释不能自动变成产品实测参数。

知识文件在服务启动时读取，不热更新。修改知识后执行知识校验和相关后端回归，并重启服务；旧报告不会自动重算，需要重新生成。验证入口见 [联调说明](联调说明.md)。

报告审计保存 `knowledgeVersion`、`matchedEntryIds`、`conflicts`、`dropped`、`reason`。当前知识版本由条目数量和约束版本组合，不是内容哈希；同数量换条目且不升级版本时，该字符串不能唯一识别内容，需同步维护版本及 Git 记录。周期摘要的来源哈希负责检测数据变动，不替代知识版本管理。

自动化测试证明的是契约、权限、规则和失败路径，不证明模型识别质量、临床有效性或商业效果。真实模型、文献与儿童共创语义质量需要独立评测。
