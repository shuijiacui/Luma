## 必须优先修复

### F01 · P0：匿名报告请求可导致服务进程退出【运行复现】

- 位置：`server/src/routes/analyze.js:73`，`server/src/services/retrieve.js:10`。
- 请求：`POST /api/report`，JSON 为 `{"features":{"elements":{}}}`，无需登录。
- 结果：`features.elements?.includes is not a function`；Express 4 的 async handler 没有捕获该异常，当前 Node 24.15.0 进程退出码 1。
- 影响：单个无效请求即可中断服务，影响所有家庭。现有检查只确认 features 为 object，没有校验内部字段，也没有统一接住异步拒绝。
- 修复：严格校验请求结构、长度、数组成员及数值范围；所有异步路由包裹 catch/next；返回规范 400/500；在独立进程里验证错误请求后健康检查仍然可用。

### F02 · P1：登录过期后“完成”成功，但画作不入库【运行复现】

- 位置：`server/src/app.js` 的可选认证中间件，`server/src/routes/analyze.js:49`，`frontend/src/lib/api/authFetch.ts`。
- 触发：儿童 access token 到期，前端仍持有它并提交画作。
- 结果：HTTP 200、没有 analysisId、数据库新增 0 条。前端自动刷新只在 401 时触发，因此不会刷新。
- 影响：孩子看到完成反馈，家长永远查不到这次作品；report 同样可能以匿名方式返回但不回写。
- 修复：区分没有提供 token 的游客和提供了无效 token 的登录请求；后者必须 401。登录状态下还应核验成功响应确实带持久化 ID。

### F03 · P1：报告入口已挂载，但跨设备与历史补生成仍不通【静态确认＋接口复现】

- 位置：`frontend/src/features/auth/pages/ParentDemoPage.tsx:1057`、`frontend/src/features/parents/components/DrawingInsightSection.tsx:119`、`server/src/routes/analyze.js:75`。
- 当前入口位于概览展开“完整解读”后，README 的“尚未挂载”已经过时。
- 生成按钮依赖 sessionStorage 的 `luma_latest_features`；家长在另一设备或新标签页没有它，即使服务端已有作品也不能生成。无报告的历史行被 disabled。
- 接口仅传合法 analysisId 仍返回 400 `features required`，尽管服务端数据库已经有完整 features。
- 修复：真实家庭按选中的 analysisId 生成，由后端鉴权后读取特征；支持所有未解读历史作品，游客另用临时输入；完成后刷新概览、历史、趋势和建议。

### F04 · P1：重复分析污染特征，清空画布后旧特征继续参与【运行复现】

- 位置：`server/src/services/extractFeatures.js:90`，`frontend/src/features/child/pages/ChildCreatePage.tsx` 的 handleFinish 和清空按钮。
- 当前每次上传完整画布，但 mergeFeatures 对涂改累加、元素和扭曲取并集。相同特征两次合并：涂改 2 → 4；删除树后再次分析，tree 仍存在。
- 清空只调用 canvas.clear，没有重置 features。新画可混入上一幅画的线索；每点一次完成还创建一条独立历史记录，重复作品会影响计数。
- 新颜色维度被门控丢弃后，又回退旧 colors，复现得到 colors 存在且最新置信度为 0.1。当前维度置信度与实际参与判定的值失配。
- 修复：完整图像分析以当前快照为准；若需版本比较则单独建版本与差异数据，不能把完整画面当作新增部分累加。清空开启新作品，重复提交应有作品 ID/幂等策略。

### F05 · P1：孩子可以读取和生成家长报告【运行复现】

- 位置：`server/src/routes/analyze.js:82`，`server/src/services/historyService.js` 的 attachReport、listAnalyses、trendSummary。
- 孩子自己的 token 调用 report 返回 200；调用 analyses 返回 200 且包含完整 report。
- 影响：目前只做了前端界面隔离，未实现“判定只给家长”的服务端权限边界。不是跨家庭数据泄漏，但确实违反角色设计。
- 修复：报告生成、报告详情、趋势限定家长；儿童历史只返回画作和描述性反馈；匿名演示报告应与真实家庭数据接口分离。

### F06 · P1：模型描述被展示为“孩子原话”【静态确认】

- 位置：`frontend/src/features/auth/pages/ParentDemoPage.tsx:239`、`:1005`，`frontend/src/features/parents/components/dashboard/OverviewDashboard.tsx:95`。
- rawDescription 来自视觉模型的画面描述，前端赋给 quote，统一署名“—— 孩子原话”。系统没有采集对应的孩子原话。
- 影响：家长会把模型生成内容误认为孩子表达，破坏创作记录的来源可信性。
- 修复：明确标记“AI 画面描述”；未来如采集原话，必须独立字段并记录来源。

### F07 · P1：多孩子切换缺乏完整的数据隔离与请求时序控制【静态确认】

- 位置：ParentDemoPage 的 analyses effect（约 325 行）、ArchivePage 的 analyses effect（约 64 行）、DrawingInsightSection 的 report state 与 handleGenerate。
- 概览和档案没有取消旧请求或校验请求序号。A 请求慢、B 请求快时，A 的结果会最后覆盖 B；概览甚至没有在切换时清空旧作品。
- 解读组件虽对历史请求加入序号保护，但切换 childId 不清空当前 report；生成所用 sessionStorage ID 也不与选中孩子绑定。同家庭 A 的报告可能显示在 B 页面下，后端家庭权限不会阻止此类错误选择。
- 修复：数据状态按 childId/analysisId 建键；切换时重置；所有请求和生成回调核验归属并丢弃过期结果。

### F08 · P1：信息不足被升级为平稳，概览改写了后端语义【运行复现＋静态确认】

- 位置：`server/src/services/historyService.js:92`；`frontend/src/features/auth/pages/ParentDemoPage.tsx:107`、`:174`。
- 两份 emotion=信息不足、confidence=0 的报告产生 direction=stable，前端对应文案为“状态平稳”。
- 概览将“未见明显风险信号”映射成“平稳积极”，又把信息不足的 0 分抬成至少 12。证据不足、未命中风险、积极证据被混淆。
- 修复：聚合时区分有效报告与信息不足；不足不能转成稳定；保留后端情绪语义和原始分值，不以视觉占位值替代真实结果。

## 其他功能与一致性问题

### F09 · P2：网络失败被当作没有作品，继而显示示例【静态确认】

ParentDemoPage 的 listAnalyses catch 将结果设为 []，空数组又触发 DEMO_OVERVIEW、DEMO_INSIGHT。页面虽标注示例，但会错误告知真实家庭“孩子还没有真实创作”。应区分加载、失败、空结果、游客，提供重试。家长页面也没有后台新增作品的轮询或回到窗口刷新，不能保证文案承诺的自动替换。

### F10 · P2：完整档案与长期趋势被固定 LIMIT 截断【运行复现】

`historyService.js:31` 最多返回 50，趋势在过滤 report 前只取最近 30。数据库有 55 份时：档案 50、trend.total 30。没有分页和真实 total，90/180 天时间轴只基于最多 50 条，旧报告还可能被新未解读作品挤出。应分页读取历史，服务端独立聚合时间范围与报告序列。

### F11 · P2：月份排序与时间窗口不正确【运行复现＋静态确认】

ArchivePage:35、TimelineSection:39 对“2026年9月”等显示字符串排序，复现升序是 10 月、11 月、9 月；应使用时间戳或 YYYY-MM。ParentDemoPage:148 在近 28 天无作品时退回所有历史，但 periodLabel 仍是“过去 4 周”，应展示该时间窗为空或明确改变范围标签。

### F12 · P2：无孩子的家长和游客进入完整档案会一直加载【静态确认】

ArchivePage:65 在无 selectedChild/token 时直接 return，analyses 永远保持 null；游客也有进入完整档案的链接。应为游客、尚未绑定孩子、请求失败分别收敛状态，不无限显示“加载中”。

### F13 · P2：报告生成后概览不会同步更新【静态确认】

DrawingInsightSection.handleGenerate 只调用自身 loadHistory，父组件没有刷新回调。生成成功后，概览仍使用之前 report=null 的 analyses，可能继续展示“等待解读”和空建议。应共享查询缓存或向父组件发送更新事件。

### F14 · P2：token 刷新只更新 localStorage，不更新 React session【静态确认】

authFetch.refreshTokens 调 saveSession，AuthProvider 只通过 useState(getStoredSession) 初始化，未订阅刷新。随后 JSON 请求和图片请求继续发送旧 token，产生重复 401/轮换，且与 F02 叠加导致 analyze 继续以匿名成功。刷新应统一更新内存认证状态，请求优先使用当前有效 token；退出/切换账号时应防止在途刷新写回旧账号。

### F15 · P2：年龄调制设计缺少真实数据来源【静态确认】

后端 dispatcher 支持 childAge，但账号表没有生日/年龄字段，注册不采集，前端 fetchReport 也不传；正常产品链路始终 null。当前不能称为已实现按年龄调制，应补档案字段并由服务端读取可信年龄。

### F16 · P2：画板的输入信息不足以实现真实笔压/擦改历史分析【静态确认】

DrawingCanvas 使用固定 brushSize，不记录 pointer pressure；橡皮用 destination-out 擦除像素。最终只发 PNG，已擦掉的内容和操作次数无法从这张图完整恢复。因此模型提取的 pressure/erasureMarks 只能是图像外观推测，不能当作真实用力程度或操作次数。若设计需要真实过程特征，应采集有定义的笔触事件，区分视觉特征与行为特征。画布也未使用已有 getChildDraft，离开画板再回来无法恢复未提交作品。

### F17 · P2：图片保存与备份恢复链路不完整【静态确认】

backup.mjs 只备份 SQLite，不备份 uploads；恢复数据库不能恢复画作文件。analyze 先写图片再写数据库，后者失败没有补偿清理，留下孤儿文件；没有图片/分析删除接口。应建立图片与数据库的配套备份、恢复校验、孤儿清理和删除流程。另 cron 不加载 server/.env，自定义 DB_PATH/BACKUP_DIR 仅写在 .env 时不会被备份进程自动继承。

### F18 · P2：RAG 配置与报告延迟仍需工程补齐【静态确认，未调用外部服务】

referenceRag 默认 Python 路径固定为 Windows 的 `.rag-venv/Scripts/python.exe`，Linux systemd 部署需显式 RAG_PYTHON。embedding 复用 LLM_BASE_URL/LLM_API_KEY，不能独立配置不同 embedding 服务商。报告增强按叙述、证据改写、文献、搜索顺序等待；单模型调用最多约 273 秒，文献超时 120 秒，没有整体时限、任务状态或请求取消联动。扩展失败虽能降级，用户仍可能长时间等待。应分离配置、设置整体预算，先返回基础报告或采用异步增强任务。

## 建议验收顺序

1. 先修 F01，加入畸形输入与错误请求后服务仍可用的进程级检查。
2. 修登录过期、作品 ID/版本、特征快照，保证“成功就保存，画面与特征一致”。
3. 将家长报告改为服务端 analysisId 驱动，完成跨设备、历史补生成和角色隔离。
4. 修多孩子隔离、来源标记、信息不足语义与各视图同步。
5. 补分页、时间范围、错误/空态、年龄字段和备份恢复。
6. 再验收真实模型、移动端作画与慢网，并对尚未交付的付费/导出功能明确展示开发中或完成实现。

建议端到端验收场景：家长设备 A 注册 → 孩子设备 B 加入 → access token 过期 → 完成作品仍成功入库 → 家长 A 无任何 sessionStorage 特征也可生成 → 切换两个孩子不串数据 → 历史未解读作品可补生成 → 55 份以上记录与跨月份统计正确 → 信息不足不显示稳定 → 错误请求不影响其他用户 → 备份恢复后原图仍可读。
