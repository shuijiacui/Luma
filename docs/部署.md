# 生产部署指南

> 当前单进程部署与数据运维说明。建议 Node.js 24、Linux VPS、Caddy HTTPS、systemd 和定期备份。以下命令是部署方案，不代表目标环境已经完成上线验收。开发启动与回归步骤见 [联调说明](联调说明.md)。

## 形态与准备

Node 进程托管 `/api/*` 和前端 dist；SQLite 保存家庭、可续画作品及笔迹文档、分析与报告，`UPLOAD_DIR` 保存分析展示图片。可续画作品图片直接存于 SQLite，不能只备份上传目录。新报告使用仓库中经核对的文献来源卡片，不需要 Python；原始 PDF 检索是独立的离线研究工具。

```bash
sudo useradd -r -M -d /opt/luma luma
sudo install -d -o luma -g luma /opt/luma
sudo -u luma git clone https://github.com/shuijiacui/Luma.git /opt/luma
cd /opt/luma/frontend
sudo -u luma npm ci
sudo -u luma npm run build
cd /opt/luma/server
sudo -u luma npm ci --omit=dev
```

已有 luma 用户或已有检出目录时复用相应步骤。依赖安装需访问包仓库；发布前检查当前依赖审计结果，并按实际变更完成兼容性复验。

## 环境配置

将 [server/.env.example](../server/.env.example) 复制为 `server/.env`，设置服务实际可用的模型名称和密钥，不把示例名称当作账号已开通能力。`server/src/index.js` 启动时读取该文件；生产启动为 `npm --prefix server start`，开发使用 `npm --prefix server run dev` 自动重载。

```dotenv
LLM_BASE_URL=https://你的兼容服务地址
LLM_API_KEY=填入服务端密钥
LLM_VISION_MODEL=账号实际可用的视觉模型
LLM_TEXT_MODEL=账号实际可用的文本模型
PORT=3001
TRUST_PROXY=1
FRONTEND_DIST=/opt/luma/frontend/dist
DB_PATH=/opt/luma/server/data.sqlite
UPLOAD_DIR=/opt/luma/server/uploads
BACKUP_DIR=/opt/luma/server/backups
BACKUP_RETENTION_DAYS=14
REPORT_BUDGET_MS=20000
PERIOD_REPORTS_ENABLED=1
```

仅在可信反代后使用 TRUST_PROXY=1，并限制外部直接访问 API 端口。密钥文件仅运行账号可读。生产同域不依赖 CORS；若另设前端域名，将其加入 CORS_ORIGINS。DB_PATH 与 UPLOAD_DIR 使用绝对路径，保证服务、备份、媒体审计一致。

默认前端构建可在同站点访问官网、家长和儿童路由。需要独立部署三个入口时，使用 `build`、`build:parent`、`build:child` 各自构建，并在产物覆盖前分别部署或指定不同输出目录；通过 `VITE_PORTAL_URL`、`VITE_PARENT_APP_URL`、`VITE_CHILD_APP_URL` 指向实际入口。三条构建命令默认共享 `frontend/dist`，不能连续构建后把最后一个目录当作三个独立产物。跨域 API 使用 `VITE_API_BASE_URL` 并配服务端 CORS。

### 可选语音与离线文献检索

绘画/画面识别模型、语音、离线文献检索 embedding 分别使用 `LLM_*`、`VOICE_*`、`RAG_EMBED_*` 凭据，程序不自动借用其他服务的密钥。未配置模型仍可验证账号与作品保存；真实画作识别和共创规划需要视觉服务。

语音示例将 `VOICE_ASR_ENABLED=false`、`VOICE_TTS_ENABLED=false`，使用浏览器识别和朗读，无需另启 Python 语音服务。ASR 与 TTS 可以独立启用；如后续需要跨设备统一的云端音色，可单独设置 `VOICE_TTS_ENABLED=true`，保留浏览器识别，并配置百炼北京 `VOICE_PROVIDER=dashscope`、`VOICE_BASE_URL`、独立 `VOICE_API_KEY`、`VOICE_TTS_MODEL=qwen3-tts-flash`、`VOICE_TTS_VOICE=Mochi`。也支持 OpenAI-compatible 音频接口，实际模型/音色必须由供应商支持。详见 [Nilo API 与语音配置](../server/NILO_API.md)。

麦克风在生产环境需要 HTTPS 与用户授权，localhost 开发例外。没有云端语音配置时，只有支持浏览器识别的设备才可降级；浏览器降级也可能依赖在线服务。云端 TTS 结果只允许从实现中列出的可信音频主机下载，其他地域需核对兼容性，不能开放任意下载域名。部署后分别验收 ASR 与 TTS，`/voice/config` 能力为 true 只表示配置存在。

新报告的研究背景来自 `knowledge/psychology/literature/curated-context.json`，随代码部署，附原文链接和适用局限，不读取原始 PDF，也不参与单幅画的判断。离线文献 RAG 需要 Python 依赖、`knowledge/psychology/references` 中的 PDF、本地 `knowledge/psychology/chroma` 索引，以及独立 embedding 配置。按 [rag/README](../rag/README.md) 建索引；手动 Python 命令需要把 `RAG_EMBED_*` 放入该进程环境，它不会自动读取 `server/.env`。重建索引会重建对应 collection，不是增量追加。不要将尚未核对的检索段落直接接入面向家庭的报告。

## 服务、HTTPS 与任务

```bash
sudo chmod 600 /opt/luma/server/.env
sudo chown luma:luma /opt/luma/server/.env
sudo cp /opt/luma/deploy/luma-server.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now luma-server
# 修改 deploy/Caddyfile 中的域名后安装并重载 Caddy
sudo cp /opt/luma/deploy/Caddyfile /etc/caddy/Caddyfile
sudo systemctl reload caddy
```

`deploy/backup.cron` 提供每日 03:30 的备份行，请将该行添加到运行账号已有 crontab，不直接覆盖其他任务。后端运行期间会写入日志；部署方负责权限、轮换和保留期限。备份任务只在执行时清理过期包，需监控任务是否成功。

周期报告由 Node 启动时和每小时自动补齐，不需要额外 cron。`PERIOD_REPORTS_ENABLED=0` 可关闭定时任务，页面读取仍补齐。手动执行：

```bash
cd /opt/luma/server
sudo -u luma npm run reports
sudo -u luma npm run backup
sudo -u luma node scripts/media-audit.mjs
```

周期报告不调用模型、不发通知；付费订阅与订单服务没有部署项。

### 周期生成与缓存

服务启动及每小时补齐已结束周期；`PERIOD_REPORTS_ENABLED=0` 只关闭后台任务，页面读取和手动 `reports` 命令仍可补齐。任务同步读取全部分析历史，没有增量队列、分布式锁或跨实例协调，扩大数据量前需评估阻塞。时区、来源范围和缓存规则统一见 [架构设计](架构设计.md)，请求字段见 [API 契约](API契约.md)。

## 备份与恢复

新备份使用 SQLite 一致性快照，内嵌所有被引用图片的字节、SHA-256 与可移植文件名。缺图或哈希不符时失败，不把不完整包当作成功。备份 CLI 自动读取 server/.env。

恢复目标必须是不存在的新目录，不能把备份包直接覆盖线上 data.sqlite：

```bash
sudo systemctl stop luma-server
sudo -u luma node /opt/luma/server/scripts/restore.mjs /opt/luma/server/backups/luma-实际时间.sqlite /opt/luma/restored-new
# 核验后修改 server/.env：
# DB_PATH=/opt/luma/restored-new/data.sqlite
# UPLOAD_DIR=/opt/luma/restored-new/uploads
sudo systemctl start luma-server
```

恢复脚本先检查数据库完整性及全部原图哈希，再输出新的 data.sqlite 和 uploads。旧的仅数据库备份不一定包含可恢复原图，不能当作新格式完整包。

注销不会重写所有历史备份。恢复历史包可能恢复随后删除的数据，正式恢复前应核对备份后的删除事项，必要时在隔离环境重做清理，再开放服务。当前没有独立于备份的永久删除墓碑机制。

## 删除、注销与留存

家长单幅删除针对分析记录：暂存对应受控图片，事务删除分析、单幅报告和周期缓存，失败则回滚并恢复图片；成功后清理暂存文件。**该操作不删除 `artworks` 中独立保存的可续画作品。** 当前没有单独删除儿童账号、第二位家长迁移或解绑重组家庭流程。

家庭注销要求同家庭家长密码复核及精确确认文案“删除整个家庭”。事务删除该家庭全部分析、报告、画册及笔迹文档、周期摘要、账号、邀请码与 access/refresh 会话；数据库失败恢复暂存图片。提交后媒体清理失败会返回 `pendingMedia`，需检查日志和媒体审计。正在等待模型的分析在持久化前再检查账号及画册版本，防止注销后重新落库。

| 数据位置 | 删除/注销后的处理 |
| --- | --- |
| 在线 SQLite 逻辑记录 | 按接口范围清除；不承诺底层磁盘取证级擦除 |
| 在线受控图片 | 提交后清除；失败暂存交给运维检查 |
| 周期摘要 | 删除分析时失效，家庭注销时清除 |
| 日志与诊断记录 | 由部署方轮换和清理，注销不清空全站日志 |
| 既有备份 | 后续成功执行备份任务时按保留天数清理；没有运行任务不会自行过期 |
| 已下载 HTML/JSON/PNG、浏览器偏好 | 用户自行保管或清除，服务端不能远程撤回 |
| 外部模型、搜索、embedding 服务 | 按所选供应商配置与协议处理，不承诺跨服务即时删除 |

共创语音录音、完整转写与孩子对话不写入本项目数据库或 trace；共创 trace 只保留类别、时延、数值用量等元数据。这不等于外部语音/模型供应商完全不留存。报告分析链有独立审计日志，不应把共创的日志限制扩大解释为全项目零内容日志。

## 验收与运行限制

健康接口 `{ok:true}` 只验证进程。上线需额外验证 SPA、HTTPS、真实家庭跨设备流程、实际模型调用、限流、日志、备份恢复和设备画布。新数据库会自动增量建表/加列，先备份再升级；旧报告不会自动按新知识库重算。

媒体审计默认只报告缺图及超过一天的无引用受控文件。核实后显式加 `--remove-orphans` 才清理普通 `.bin` / 暂存删除文件，不跟随符号链接；家庭注销返回 pendingMedia 非零时应检查相应日志。不要通过删除整个上传目录来处理孤儿文件。

当前使用同步 SQLite、进程内任务与限流，没有多实例协调。日志保留、备份权限与轮换、外部服务数据处理由部署方配置。前端资源仍有体积优化空间，自动化构建通过不能代替弱网和真实设备验收。

共创预览新增纯 JavaScript 依赖 pngjs，更新后在 server 执行 npm ci 并重启。部署需同时保留仓库的 shared/niloSketch.mjs 与 shared/niloGeometry.mjs，后端和前端共用这些绘图定义；不要只单独复制 server 目录。
