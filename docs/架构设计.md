# 架构与数据流

> 更新于 2026-09-18。本文件说明模块边界和数据流；操作步骤见[功能与使用流程](功能与使用流程.md)，字段见[API 契约](API契约.md)。

## 1. 应用与服务

Luma 使用 React 19 / TypeScript / Vite 前端、Express API 和 Node.js 内置 SQLite。官网、家长端、儿童端复用代码，按 `appMode` 构建不同路由集合。

开发时三个前端分别使用 5173、5174、5175，通过 `/api` 代理访问 3001 后端。前端 `dev` 同时启动三个前端，后端需单独启动。生产可以同域托管，也可以配置独立端地址。

| 模块 | 责任 | 主要代码 |
| --- | --- | --- |
| 路由、会话、语言 | 三端入口、角色保护、令牌刷新、共享词典 | `frontend/src/app`、`features/auth`、`i18n`、`shared/locales` |
| 画布与笔迹 | 笔刷、坐标、操作文档、投影、分组撤销、等比适配 | `frontend/src/features/child/components`、`canvasDocument.ts` |
| Nilo 共创 | 有限上下文、主动邀请、请求取消、自定义线稿编译、提案验证和确认 | `useCompanion.ts`、`companion/proposals.ts`、`companion/sketch.ts`、`server/src/services/niloDialogue.js` |
| 语音 | 显式收音、识别、播报、打断、浏览器降级 | `useCompanionVoice.ts`、`server/src/services/voice.js` |
| API 入口 | JSON、白名单 CORS、限流、认证、静态托管、错误处理 | `server/src/app.js` |
| 家庭与账号 | scrypt、会话、邀请码、生日、家庭注销 | `routes/auth.js`、`authService.js`、`familyDeletion.js` |
| 保存与分析 | 可编辑作品、版本冲突、视觉特征、描述反馈、原图权限 | `routes/artworks.js`、`routes/analyze.js` |
| 解读与增强 | 规则调度、评分、审计、可选说明/搜索/文献 | `kbDispatcher.js`、`score.js`、`report.js`、`referenceRag.js` |
| 历史与周期 | 分析历史、描述性趋势、已结束周期摘要 | `historyService.js`、`periodReports.js` |
| 运维 | 内嵌图片备份、哈希校验恢复、媒体审计 | `server/scripts/` |

## 2. 四条数据流

### 保存与续画

儿童绘画 → 导出已确认合成图和笔迹文档 → `/artworks` 保存版本 → 儿童历史页读取 → 重放并续画。

此链路不调用模型。正式儿童数据写入服务端 `artworks`；游客使用浏览器本地存储。未保存草稿仅存在页面内存。仅保存不会新增家长分析历史。

### Nilo 共创

孩子点击头像或明确语音邀请 → 导出已确认合成观察图及作者摘要 → `/nilo/companion` 单次规划 → 前端修正比例并校验实际笔迹碰撞 → 临时投影 → 孩子明确确认 → 一次提交整个 Nilo 笔迹组。

规划最多包含 4 个相关元素，可混合使用 21 种基础模板与自定义线稿。模型生成有界的 M/L/Q/C/Z 路径或独立椭圆 E；服务端与前端严格校验后，本地将曲线采样为笔迹。整组最多 64 条笔迹、192 条自定义几何指令，每个自定义物体最多 24 条路径、96 条指令；不执行 SVG、脚本或外部资源。物体自身的设计宽高比在不同画布尺寸下保持一致。

前端沿用相同的笔刷渲染器绘制预览和最终路径，确认时原子提交并按组撤销；保存仍使用已有笔迹文档，无需迁移旧作品。模型无权确认或删除作品。投影不进入保存、下载、分析或下一轮观察图。自定义物体的近期接受/拒绝记忆使用名称，不把拒绝一次自定义提案扩大为禁止整个能力。

请求绑定画布版本和账号/作品身份。孩子继续画、切换模式或作品、页面隐藏、真实画布尺寸改变、取消和超时都会使旧响应失效。点击头像只交接绘画回合，不启动麦克风或 TTS。

### 完成与儿童反馈

点击“完成” → 先保存作品 → 分离孩子笔迹 → `/analyze` 校验作品关联和来源 → 视觉特征提取、schema 校验、逐维门控 → 描述性反馈 → 正式账号保存 `analyses` 和展示图片副本。

家长看到的图片可以是已确认合成图；分析输入只使用孩子层。旧 PNG 来源未知时允许保存，不生成新的儿童特征分析。分析失败不会撤销已成功保存的作品。

同孩子、同提交键和同图像的重试返回已有记录，提交键不能复用于不同内容。特征来自当前快照，不把已经擦除的元素累积进新报告。

### 家长解读与周期汇总

家长选择 `analysisId` → 同家庭鉴权 → 服务端读取特征和生日 → 知识库调度、确定性评分与审计 → 基础报告 → 可选文字解释/文献背景/联网建议 → 保存解读。

已有分析与报告再用于主题、时间轴、沟通建议、趋势和周期摘要。家长沟通助手组织建议卡片，未提供自由聊天服务。周报/月报不调用模型。

视觉提取和可选解释可能各自调用外部模型。可复现的是给定特征、知识库与配置时的规则结果，不保证图像模型每次输出相同。具体门控、公式和输出语义统一见 [AI 解读与知识库](AI解读与知识库.md)。

## 3. 笔迹、来源和声音状态

笔迹文档包含 `version`、可选底图及来源、`coCreated` 标记和 `operations`。每笔记录作者、分组、归一化点、笔刷、颜色、粗细、橡皮状态及参考绘画尺寸；清空也是一种操作。儿童撤销和 Nilo 撤销按各自最后一组执行。

曾接受 Nilo 内容的作品保留共创标记，即使随后撤销 AI 笔迹，也不把创作过程重新称为完全独立。未知旧底图不会伪造作者身份。边界摘要是保守几何提示，不等于逐像素语义分割。

`DrawingSurface` 保持已有作品的物理纵横比；左侧工具区固定预留空间，开合工具不触发画布缩放。像素密度和 CSS 线宽分别处理，避免高分屏把笔刷放大两次。

语音状态与绘画模式独立。收音须主动开启；识别最终文本才交给指令解析，赞美和模糊回应不接受投影。连续语音有轮数和时长上限；离开页面或停止时释放录音与播放，音乐自动恢复原音量。原始录音与完整转写不写数据库或 trace。协议和配置见 [Nilo API](../server/NILO_API.md)。

## 4. 持久化模型

| 数据 | 内容与作用 |
| --- | --- |
| `families` | 家庭 ID、邀请码 |
| `accounts` | 身份、家庭、昵称/邮箱、密码或创作码哈希、可选生日 |
| `sessions` / `refresh_tokens` | access 会话、refresh 哈希及过期时间 |
| `artworks` | 儿童可编辑的 PNG base64、笔迹文档、来源、版本与更新时间 |
| `analyses` | 家庭/孩子、特征、描述反馈、展示图元数据、解读与审计、提交键 |
| `period_reports` | 周期边界、摘要 JSON、来源哈希、生成时间 |
| `UPLOAD_DIR` | 分析展示图片等受控媒体，通过授权接口读取 |
| 浏览器本地存储 | 游客已保存作品、头像、语言/声音/工具偏好、简短共创故事、引导记录 |
| 页面内存 | 未保存草稿、当前对话、待确认投影与正在执行的请求 |

启动时增量建表/加列，不自动重新解释历史报告。`artworks` 与 `analyses` 有不同生命周期：家长删除单幅分析不会删除儿童可编辑原稿；注销整个家庭则同时删除两类记录。媒体事务、留存与恢复见[部署](部署.md)。

## 5. 会话与权限

access 默认 120 分钟，refresh 为 30 天并轮换；退出撤销该账号的会话。前端并发刷新共享请求，过期响应不得在退出或换账号后恢复旧会话。

- `/artworks` 仅正式儿童账号操作自己的记录；游客由前端本地保存。
- 分析历史和图片按家庭与孩子授权，儿童读自己的分析时不返回家长报告。
- 正式报告、趋势、周期摘要、生日修改和分析删除仅同家庭家长可用。
- 匿名可执行受限的临时分析/报告演示，不能使用真实作品编号读取家庭数据。
- 图片使用 `Authorization` 请求头读取，认证令牌不放在 URL 或导出文件中。

权限由服务端检查；页面是否显示按钮不构成访问控制。

## 6. 周期任务

摘要来源是 `analyses`，不是所有仅保存的 `artworks`。按 `Asia/Shanghai` 的已结束周期汇总：周一 00:00 至下周一 00:00，自然月 1 日至次月 1 日；数据库边界为 UTC ISO，左闭右开。没有记录和未结束的周期不造摘要。

元素在同一记录内去重，最多展示 12 种；已有建议去重后最多 6 条；创作天数按本地日期去重。比较相邻自然周期的记录数量，不把数量变化解释为心理变化。

启动、每小时任务和家长读取均可补齐。唯一键为 `(child_id, kind, period_start)`，来源哈希变化时更新；修改解读或删除分析使旧摘要失效。摘要重新生成后 ID 可能变化，集成方应以孩子、周期类型和边界识别逻辑周期。

`PERIOD_REPORTS_ENABLED=0` 只关闭后台任务，不关闭手动命令和页面补齐。嵌入式使用可调用 `app.locals.closeBackgroundJobs()` 清理定时器；测试默认不启动后台任务。

## 7. 开发与扩展边界

双语、引导系统、角色素材和布局维护集中在[前端说明](../frontend/README.md)。操作验收集中在[联调说明](联调说明.md)，不再用阶段总结中的旧测试数量作为当前验收结论。

主服务可同域托管前端；基础规则不依赖 Python。可选文献检索通过 Python 子进程访问本地 Chroma，embedding 配置独立于视觉/文本模型。

当前是同步 SQLite、进程内限流与定时任务，没有跨实例协调、分布式队列或支付系统。多实例扩展需要重新处理存储、任务和限流；长历史汇总的阻塞时间、真实设备和模型效果需要单独验收。

旧设备方案中仍有价值、但尚未实现的工程方向保留在此：

| 待研究方向 | 实施前需要验证 |
| --- | --- |
| IndexedDB 离线草稿与持久上传队列 | 按账号隔离，区分本机保存/待上传/已同步，处理容量和冲突；服务重启后可恢复任务 |
| PWA 与双角色安装 | 缓存隔离、版本更新不打断创作；不能把令牌和跨家庭图片混入公共缓存 |
| 一次性设备配对与家长通知 | 短时配对只授儿童权限，二维码不带家长令牌；通知不暴露敏感报告 |
| 手写笔与防误触 | 在目标平板实测延迟和手掌误触；压力仅用于笔触，不自动进入心理分析 |

这些是后续评估方向，不是当前服务承诺；素材摆放、指点命名和可纠错记忆等研究问题见[研究依据](研究依据.md)。
