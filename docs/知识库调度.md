# 知识库四层构建与调度

> 知识库不是一锅 JSONL，而是**四层异构知识 + 一个专属调度器（dispatcher）**。
> 数据文件：[entries.jsonl](../knowledge/entries.jsonl)（L1–L3）、[constraints.json](../knowledge/constraints.json)（L4）、[dispatch.config.json](../knowledge/dispatch.config.json)（调度策略）。校验：[scripts/validate.mjs](../knowledge/scripts/validate.mjs)。

## 四层构建

```
┌─────────────────────────────────────────────────────────────┐
│ L4 元认知层（constraints.json）——不下场，全程当裁判            │
│   效度天花板 0.85 │ 年龄发育调制 │ 冲突登记 │ 负证据 │ 红线词   │
├─────────────────────────────────────────────────────────────┤
│ L1 实证层（tier:1，26 条）——主判定                            │
│   含定量数据：Yan OR值 / Guo 预测特征 / Li Rasch / 儿童实证    │
│   reliability 0.7–0.9，strength ≤ 0.6，唯一可独立支撑预警      │
├─────────────────────────────────────────────────────────────┤
│ L2 体系层（tier:2，2 条）——交叉验证                           │
│   Buck 1948 框架 / Koppitz 指标：结构完整但效度有争议          │
│   reliability 0.4–0.6，strength ≤ 0.2，不可独立触发           │
├─────────────────────────────────────────────────────────────┤
│ L3 经验层（tier:3，2 条）——共现加成                           │
│   FBANet 定性观察等：仅当同情绪组已有 L1 命中时才计入           │
│   reliability ≤ 0.3，strength ≤ 0.2                          │
└─────────────────────────────────────────────────────────────┘
```

### 为什么要分层而不是一个 reliability 字段打天下

reliability 只表达"来源可不可信"，分层额外表达**使用权限**——这是两回事：

| 层 | 能做什么 | 不能做什么 | 对应防幻觉机制 |
|----|---------|-----------|--------------|
| L1 实证 | 独立支撑预警（仍受阈值+天花板约束） | 强度超 0.6 | 定量证据才可定生死 |
| L2 体系 | 与 L1 交叉验证、补充共现 | 独立触发预警（组证据全来自 L2+L3 → E 截断 0.6 → 信息不足） | 经典体系不能单独定案（Lilienfeld 2000 效度质疑） |
| L3 经验 | L1 已命中时加成 | 任何独立贡献（cooccurrenceRequired） | 定性观察永远只是旁证 |
| L4 元认知 | 调制、拦截、截断、登记 | 被特征直接命中 | 负证据和发育常模是规则不是条目 |

## 调度器（server/src/services/kbDispatcher.js）

```
FeatureJSON(含c+年龄)
      │
      ▼
┌─────────────┐  1. 冷启动按 tier/emotionSignal/cluster 三维索引
│ kbDispatcher│  2. L4 先行：ageMods 按年龄段调制 c 因子
└──────┬──────┘  3. L1 全量标签匹配
       │          4. L2 匹配 → strength 压 cap 0.2
       │          5. L3 匹配 → 检查同组 L1 共现门槛，不满足则丢弃
       ▼
  score.js v2 六步（w_eff → 簇内max → noisy-OR → 贝叶斯 → 天花板 → 判定）
       │
       ▼
  L4 收尾：conflictRegistry 冲突登记 → redLineWords 拦截 → ID存在性校验
       │
       ▼
  审计快照：命中条目ID + 知识库版本号 → 判定日志（家长页"判定依据"数据源）
```

### 调度规则（dispatch.config.json 声明式配置）

1. **预警必须有实证**：某情绪组的命中全部来自 L2+L3 时，该组证据强度 E 强制截断至 0.6（< 阈值 0.7），结果落"信息不足"。Buck/Koppitz 再好也不能单独定案。
2. **经验层共现门槛**：L3 条目只在同情绪组已有 ≥1 条 L1 命中时计入 noisy-OR 合成。
3. **年龄调制前置**：`ageMods.affectedEntries` 命中时，4–7 岁 c×0.5、8–12 岁 c×0.8——发育混淆条目在低龄段自动降权，不靠 LLM 自觉。
4. **冲突显式化**：命中 `conflictRegistry` 规则时按 policy 处置（作废簇 / 限制计入条件），判定日志强制记录冲突 ID——冲突暴露给家长和审计，不在黑箱里消化。
5. **版本化审计**：每次判定记录 `knowledgeVersion + 命中条目ID列表`，家长页"判定依据"直接由此渲染，天然满足"每条判定引用条目 ID"红线。

### 层的晋升与降级（知识库治理）

- **L3 → L1 晋升**：当某定性观察被新的定量研究验证 → 改 source/reliability/tier，validate.mjs 自动检查 tier↔reliability 一致性
- **L1 → 降级**：当出现高质量阴性证据 → 记入 `negativeEvidence`，strength 压上限（现有 3 条已应用）
- **禁止路径**：LLM 生成条目、无 source 条目、TBD 条目 reliability ≠ 0.1——validate.mjs 全部拦截（退出码 1）
