# Nilo 开放场景升级

本轮目标是把“魔法世界”等未预设主题接入同一条创作链，不继续增加主题关键词对应固定模板。原有简单物体直达、复杂构思确认、临时投影、素材替换和孩子原画保护继续保留。

## 实现

- 共享场景范围判断识别世界、地点、多个物体的整体构图；具体物体和局部位置修改保留短路径。
- 目录前理解只提取孩子的意思、明确物品、否定和参照，不提前把模型脑补的装饰变成要求。
- 检索先从同画风、同细节档的完整语义索引选择相关素材，再交给构图；当前默认档可搜索 167 个主体。检索结果异常时回退完整索引，不丢失能力，也不占用额外修正次数。
- 已知名词采用词边界和受控同义/上下位匹配，避免星球变皮球、乡间小屋不能满足房子等错误；不能用重命名把错误素材伪装成正确物体。
- 模型描述相对位置、承托和大小关系，确定性布局计算比例、连接和留白；支持整物倒转。真实承托面的元数据优先于图片外框，已知喷水鲸鱼不能被当作平坦背部。
- 复杂提案在确认前检查真实投影或待绘制的明确形态合同。自定义物体绘制后先检查单物体，再检查最终整场组合。检查图仅提高对比度，实际临时底图依然是虚线/密集灰底。审核不能把可选构思升级为孩子要求；无效或不完整的审核数据不能放行。
- 规划/理解/质量问题共享一次修正机会，默认总规划预算 18 秒，硬上限 22 秒；渲染上限 24 秒。没有无限重试或后台反复择优。
- 失败后“再试一次”沿用原意，绑定家庭/孩子所有者与作品；换作品或停止会失效。换素材清除失效连接，防止下次操作悄悄挪动旧道路。

## 可重复验证

在 `server` 目录运行：

```powershell
node scripts/eval-nilo-open-scenes.mjs
node scripts/eval-nilo-open-scenes.mjs --live --limit=24
node scripts/eval-nilo-open-scenes.mjs --preview=已保存的运行目录
```

默认离线，不读取凭证或访问模型。`--live` 使用已配置服务；24 条固定合成请求涵盖新主题、空间关系、大小、否定、保留原画、局部修改和英文。每个案例只进行一次完整事务，保存阶段耗时、规划、自动审核、错误、前后 PNG/SVG 和待评审清单。评审清单不发送给生成模型。

## 证据与边界

中间版本的真实试验曾出现“可渲染但不符合原话”的场景，包括鲸背房屋落在喷水上方、普通素材被描述成纸制物体、摘要保留了未画出的发光点。这些不能记作质量通过，已用于改进通用规划、布局和核验机制。

自动质量检查仍是概率性模型判断，不能代替独立看图，也不能证明任何开放要求都能满足。复杂融合、自定义线稿的精美程度、密集互动及库中缺少的姿态仍可能失败。完整生成不等于儿童喜欢；本轮合成评测不覆盖真实儿童体验、麦克风转写或平板端显示。

实质缺陷包括：

- “海底城市”只有潜水艇、鱼和水母，没有城市/居住结构；自动审核误放行。

- “魔法世界”等请求会在构图或审核阶段失败。只换 Pro 或开启推理未证明可以稳定解决，后者在现有响应预算内更容易超时。

这些结果表明通用链路已经落地，但现有模型与素材/自由线稿的组合能力仍有明显上限。此轮不能宣称“彻底解决模型不会”，也不应把质量门直接放宽来提高表面成功率。冻结批次之后的修复须区分为代码回归修复，不追溯修改这些模型结果。

最后一批三张 ready 也逐一看图：魔法世界有可辨认的奇幻素材，但主要横排，且“船在洞穴上方”与实际在左侧矛盾；糖果星球实际是甜点拼盘，缺少星球的可见形态；安静奇妙之地基本表达安静，但物件仍较分散。root AI 复核为 2 partial、1 fail，证据在该批 `review-root.json`。因此不能用这一批“3 / 6 生成”来宣称创作效果已经达标。

## 整体图像生成试验（9 月 28 日上午，尚未发布）

此前的素材组合/自由路径方案不能稳定画出融合主体，因此增加独立的场景图片生成服务。新复杂整场构思采用一张连贯的 `qwen-image-3.0` 参考图；简单物体、普通组合和已有物体修改继续使用素材及原几何。图像重新编码为有尺寸、字节和路径上限的自包含 PNG，简单线条转虚线，密集图保留灰底。生成参考不进入孩子笔迹、撤销文档或默认导出。父母聊天和语音模型不随场景配置更换。

目录前提取原话后，构图选择具体可见想法让孩子确认；以确认摘要约束实际图片，避免内部要求与孩子看到的说明相矛盾。图片先检查单图，再检查最终位置与整场。没有通过则不返回部分成图。既有孩子内容应作为保护锚点，不能成为新图里的重复主体。网络/429/5xx 仅在原事务期限内重试一次，权限和解析错误不作运输重试。

## 限额针对性修复（13:18，未发布）

用户要求减少 API 消耗后，停止整批重复验证。本轮只对变更影响的路径检查：

- 出图提示改成简洁的画面描述，保留原始要求、已存在笔迹排除、单物品变体和方向变换约束。
- 新生成的 `rotation:180` 图片必须在规划阶段给出旋转前描述，缺失时使用原有一次修复机会；既有同几何图片的移动/旋转不强迫重新生成。
- 修复“孩子画的小船正上方”被当作新图包含小船的错误。用已保存的原始失败响应离线回放，原先第二次仍失败的规划现可进入确认；没有调用服务。真实出图/保留笔迹并未在本轮重复测试。
- 测试器默认仅一个案例，总模型 HTTP 请求上限 8、出图上限 2；失败请求及运输重试都计入，超限在网络之前阻断。限额只约束测试，不改线上生产的行为。
- 本轮相关离线测试 8 文件、75 项通过；不重新运行已通过且不受影响的前端和家长端检查。

## 后续验收重点

1. 持续使用这套固定请求和独立看图，同时补充未参与调试的新请求，避免只优化已有例子。
2. 复杂融合/材质/姿态需要更强的可控生成能力；任何新模型或图像生成服务必须先对同一评测验证质量、时延和成本，再考虑接入。
3. 普通素材组合的核心是可见关系与实际功能。相关名词和漂亮摘要不代表已经表达城市、国度、庇护或冒险。
4. 当前工作区为本地实现与验证，尚未将本轮升级 push 或部署。既有家长历史记录/多孩子改动保留，不属于本报告的场景质量结论。
